A surrogate is not useful because it is accurate once. It has to remain useful inside a decision loop.

EdgeGenBench is a reproducible Scientific ML benchmark for testing how surrogate models behave when they are asked to estimate uncertainty, gate feasible designs, drive an optimizer, survive physics validation, and then run under deployment constraints.

At a glance

  • Deterministic synthetic aircraft-design data
  • Ridge, Random Forest, HistGradientBoosting
  • Split-conformal + tree-quantile uncertainty
  • False-safe-rate-aware feasibility classification
  • 20,000 optimization candidates
  • Pareto-front extraction and physics validation
  • ONNX export and equivalence checks
  • Accuracy / size / latency benchmark

The benchmark question

In engineering design, a surrogate rarely exists just to win an R² table. It is used downstream: to reject unsafe designs, estimate uncertainty, rank alternatives, or accelerate optimization. EdgeGenBench therefore evaluates a full decision workflow rather than treating prediction error as the endpoint.

The strongest accuracy, smallest model, and fastest model are not the same model. The benchmark keeps those trade-offs explicit rather than reducing model selection to one scalar.

Uncertainty and safety-aware feasibility

The workflow includes Random Forest tree-quantile intervals and split-conformal prediction intervals. A separate feasibility classifier is selected with attention to false-safe rate, because in this setting calling an infeasible design safe is more serious than rejecting a feasible one.

The optimizer changed the operating point

A classifier threshold that behaved well on ordinary validation data was not conservative enough for optimizer-selected designs. The benchmark therefore separates the classifier operating threshold from the optimization acceptance threshold and chooses the latter through direct physics validation.

From 20,000 generated candidates, 5,413 were accepted and 47 remained on the Pareto front. The current representative designs and Pareto-front checks achieved 100% feasibility agreement with the analytical physics model under the benchmark configuration.

Deployment equivalence matters too

The Random Forest surrogate and feasibility classifier are exported to ONNX and checked against the original scikit-learn models before latency is reported.

Modelscikit-learnONNX Runtime
Surrogate13.795 ms0.305 ms
Feasibility classifier14.787 ms0.311 ms

The optimization and deployment steps are part of the benchmark because a surrogate that cannot reproduce its outputs after conversion is not the same model in any operationally useful sense.

What I would build next

The next technical step is a compact PyTorch multi-output neural surrogate with GPU training, early stopping, FP16/INT8 conversion, and the same accuracy-size-latency evaluation. That extension is useful because it closes a genuine gap in the current benchmark rather than adding a neural network only for complexity.
