Grounded answers, bounded agents, and inspectable failure modes.

AeroRAG-X is an evaluation-first technical knowledge system over public NASA NTRS material. It treats retrieval, grounding, model adaptation, agentic tool use, evaluation, reliability, and deployment as separately measurable engineering problems.

Project context

The project grew from questions I became interested in while contributing to HERO, a Georgia Tech Grand Challenge project sponsored by Delta Air Lines. AeroRAG-X is independent work and uses public NASA literature only; it is not a HERO or Delta deliverable and does not contain restricted FOQA/ASAP records.

Evidence-grounded RAG

The retrieval stack combines lexical BM25 and dense MiniLM retrieval, merges rankings with Reciprocal Rank Fusion, and reranks a bounded candidate set with a cross-encoder. Retrieved chunks retain document, page, URL, and checksum provenance. An evidence-sufficiency gate determines whether the system should answer before model inference is allowed.

The model references evidence IDs rather than authoring authoritative citation metadata. The application validates those IDs and constructs citations from known source records, keeping citation authority outside the language model.

Local LLM adaptation and protected evaluation

I adapted Qwen3-0.6B with PEFT/LoRA and evaluated model and system behavior on protected, versioned benchmarks. The evaluation separates response-schema compliance from semantic behavior and preserves negative results instead of tuning them away.

Stateful agentic orchestration

A typed tool layer exposes bounded retrieval, authoritative source inspection, evidence-sufficiency assessment, citation validation, and multi-source comparison. A schema-constrained planner dynamically routes only registered tools through a LangGraph state machine.

The agent enforces graph-step, tool-call, and retrieval-attempt budgets, records inspectable trajectories, and ends with explicit terminal reasons. This makes tool use measurable and prevents unbounded autonomous loops.

Checkpointing, human review, and failure recovery

Agent state can be stored as immutable versioned checkpoints and resumed after a bounded human-review interruption. Approve, reject, and edit decisions produce validated resume states while preserving the original paused state.

Fault-injection utilities cover timeout, service-error, malformed-response, and dependency-unavailable cases. Per-tool retry policies are bounded, and unrecoverable dependency failures terminate safely rather than being converted into unsupported generation.

Distributed GenAI runtime

The application is decomposed into independently containerizable Agent API, Retrieval Service, and Inference Service processes. Docker Compose wires those services to PostgreSQL/pgvector, while typed asynchronous contracts preserve request, trace, thread, evidence, document, and citation identity across service boundaries.

OpenTelemetry trace propagation, Prometheus service metrics, health/readiness endpoints, bounded retries, and safe degradation provide the reliability surface for controlled distributed-runtime testing.

Grounded-agent GRPO experiment infrastructure

I built a TRL-compatible GRPO experiment harness for bounded grounded tool use. The reward design separately scores supported answers, grounded refusals, citation validity, evidence use, structured output, and tool-selection behavior, with penalties for unnecessary tool calls and unsupported generation.

The experiment includes anti-reward-hacking gates, explicit train/evaluation leakage controls, a bounded retrieve/sufficiency/submit/refuse environment, and paired Base-vs-LoRA/SFT-vs-GRPO held-out evaluation contracts. A genuine GRPO optimization run and measured model-improvement claim remain pending; the current repository intentionally does not fabricate those results.

Multimodal research foundation

The multimodal work currently establishes page-linked visual-asset provenance, checksum-verified whole-page rendering, deterministic render manifests, and independent-review task contracts for a small frozen slice. It does not claim OCR, automatic figure/table detection, visual embeddings, multimodal retrieval, or multimodal model-quality results.
