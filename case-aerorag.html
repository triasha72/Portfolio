Evidence-grounded answers for technical literature.

AeroRAG-X is an independent RAG system over public NASA technical literature. It is designed around a simple requirement: an answer should remain traceable to the evidence that supports it, and the system should decline to make unsupported claims.

Project context

AeroRAG-X was independently inspired by HERO, a Georgia Tech coursework grand challenge on airline safety and risk assessment. HERO involved restricted FOQA and ASAP records. AeroRAG-X does not use those records: it uses public NASA technical literature so the corpus, evaluation assets, and engineering decisions can be shared and reproduced.

Retrieval before generation

The system combines lexical BM25 and dense retrieval, fuses result lists with Reciprocal Rank Fusion, and applies cross-encoder reranking before a model generates a response. Evidence-sufficiency checks decide whether the retrieved material supports an answer. When it does not, the system preserves provenance and follows a refusal path instead of generating an unsupported assertion.

Local LLM adaptation and evaluation

I adapted a local Qwen LLM with PEFT/LoRA and built a protected evaluation framework for both the model and the RAG system. The goal was to measure evidence coverage and safe behavior, rather than treating fluent text as proof of quality.

Defined evaluation measureResult
Conservative semantic concept coverage38.2% → 51.3%
Full answer-to-claim capture10% → 45%
Broad claim-to-evidence support~90%
Safe non-assertion on grounded unsupported-query tests100%

These results describe the defined evaluation suite, not a claim of universal RAG correctness. The suite is deliberately kept separate from the development decisions it is meant to test.

Bounded adaptive retrieval

The system implements bounded adaptive retrieval in both native orchestration and LangGraph/LangChain. Evidence assessment can trigger conditional query rewriting, but the workflow is limited to a maximum two-pass retrieval policy with deterministic termination. It also preserves refusal provenance and includes parity tests between orchestration paths.

Adaptive retrieval is evaluated against single-pass RAG on recovery quality, unsupported assertions, citation integrity, latency, and retrieval overhead.

Reproducible ML-system experimentation

The platform includes Dockerized services, CI/CD, OpenTelemetry and Prometheus observability, local-inference and quantization benchmarks, multimodal text/table/figure retrieval, regression-tested evaluation suites, and versioned configurations and artifacts. The point is not to turn a retrieval demo into a large platform; it is to make system behavior inspectable, testable, and reproducible.
