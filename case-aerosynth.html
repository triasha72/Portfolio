Evaluating multimodal AI before trusting its output.

AeroSynth-Eval is a reproducible evaluation project for synthetic aerospace inspection imagery. It focuses on benchmark design, provenance, protected test boundaries, strict response contracts, and human-reviewable evaluation rather than treating a single VLM output as proof of quality.

At a glance

  • 48 frozen scenarios
  • 36 development / 12 protected test
  • 48 deterministic synthetic PNG assets
  • SHA-256 provenance
  • Pydantic + Typer contracts
  • Protected-test rejection
  • Human annotation queue
  • Synthetic agreement fixtures for CI only
  • MLX-VLM local development adapter
  • Ruff + strict mypy + pytest + GitHub Actions

The evaluation question

The project asks whether a vision-language model can evaluate a synthetic aircraft-exterior inspection image against an explicit, human-reviewable rubric while preserving exactly which asset, scenario, and evaluation request produced the result.

The goal is not to claim operational inspection capability. The goal is to make evaluation inputs, outputs, provenance, and failure boundaries measurable.

Frozen scenario design

The benchmark defines 48 scenarios across aircraft regions, anomaly types, materials, backgrounds, lighting conditions, and capture profiles. The split is frozen at 36 development scenarios and 12 protected test scenarios so development decisions cannot silently consume the evaluation set.

Deterministic corpus and provenance

Each frozen scenario is materialized as a deterministic procedural PNG with a recorded generation specification, seed, timestamp, renderer version, and SHA-256 digest. Registry and manifest checks detect missing assets, mismatched metadata, and corpus drift before evaluation begins.

Typed evaluation contracts

Pydantic and Typer define the benchmark's data and command interfaces. VLM responses are schema constrained: unexpected fields, invalid scores, malformed JSON, metadata mismatches, and protected-test requests are rejected instead of being accepted as usable evaluation records.

Human-review infrastructure

The project includes a balanced development-only annotation queue and validated reviewer-response contracts. Synthetic agreement fixtures exist only to test the analysis and CI workflow; they are not human agreement evidence and are never presented as model-performance results.

Optional local MLX-VLM runner

An Apple-Silicon MLX-VLM adapter runs one development asset at a time after verifying corpus and image integrity. The runner binds model responses to exact asset, scenario, rubric, model, runtime, prompt, and image-digest metadata before writing a local record.

This is a development inference path, not an aggregate VLM accuracy or calibration claim.

Automated reliability gates

GitHub Actions run formatting, linting, strict type checking, tests, scenario and asset validation, corpus integrity checks, annotation-contract validation, prompt preview checks, response-fixture validation, and no-inference MLX-VLM smoke plans.
